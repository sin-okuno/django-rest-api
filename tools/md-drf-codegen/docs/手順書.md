# md-drf-codegen 手順書

`product-structure.md` だけがある初期状態から、YAML 抽出 → DRF コード自動生成までの手順です。

## 前提

- Python 3.11 以上
- 作業ディレクトリは常に次のパスとします。

```text
django-rest-api/tools/md-drf-codegen
```

## 初期状態（本手順の起点）

リポジトリ上の入力は次のみです。

```text
examples/specs/product-structure.md
examples/generated/.gitkeep   # 出力先ディレクトリのプレースホルダ
```

`examples/generated/` 配下に YAML や Python 生成物はまだありません。

仕様書に必須なのは次の 2 セクションです（他セクションは無視されます）。

| セクション | 用途 |
| --- | --- |
| `## API一覧` | エンドポイント定義 |
| `## 型定義` | `カテゴリー = api` の型のみ抽出 |

---

## 1. セットアップ（初回のみ）

```powershell
cd django-rest-api\tools\md-drf-codegen
python -m venv .venv
.\.venv\Scripts\activate
pip install -e ".[dev]"
```

インストール確認:

```powershell
md-drf-codegen --help
```

---

## 2. Markdown → YAML 抽出

```powershell
md-drf-codegen extract examples\specs\product-structure.md
```

省略時の出力先:

```text
examples/generated/product-structure.yaml
```

出力先を明示する場合:

```powershell
md-drf-codegen extract examples\specs\product-structure.md -o examples\generated\product-structure.yaml
```

成功時の表示例:

```text
Wrote ...\examples\generated\product-structure.yaml
```

抽出内容:

- API一覧の全行
- 型定義のうち `カテゴリー` が `api` の行のみ（`view` / `action` は対象外）
- `string | null` などは `type` + `nullable` に正規化
- 任意列 `最大桁数` / `小数桁` は桁数チェックとして YAML・Serializer に反映
  - `string` → `max_length`
  - `integer` → `max_value`（例: 3 → 999）
  - `number` / `decimal` → `DecimalField(max_digits, decimal_places)`

---

## 3. YAML 検証（任意・推奨）

```powershell
md-drf-codegen validate examples\generated\product-structure.yaml
```

成功時:

```text
OK: ...\examples\generated\product-structure.yaml
```

参照切れやスキーマ不正があると exit code 1 で失敗します。生成前に直してください。

---

## 4. YAML → コード自動生成

```powershell
md-drf-codegen generate examples\generated\product-structure.yaml
```

省略時の出力先:

```text
examples/generated/<yaml-stem>/
```

例: `product-structure.yaml` → `examples/generated/product-structure/`

出力先を明示する場合:

```powershell
md-drf-codegen generate examples\generated\product-structure.yaml -o examples\generated\product-structure
```

### 生成されるファイル

| ファイル | 内容 |
| --- | --- |
| `<prefix>_serializers.py` | API 型の DRF Serializer（prefix は md ファイル名 stem） |
| `<prefix>_views.py` | APIView（同一パスの GET+PUT は 1 クラスに統合） |
| `urls.py` | `urlpatterns` |
| `<prefix>_handlers.py` | Handler クラス（View から直接生成） |
| `conftest.py` | 生成テスト用 fixture |
| `test_generated_api.py` | Serializer / URL / View の自動テスト |
| `__init__.py` | パッケージ化 |

例: `product-structure.md` → `product_structure_serializers.py` / `product_structure_views.py` / `product_structure_handlers.py`

View から Handler への呼び出し例:

```python
handler = LoadDetailHandler()
result = handler.handle(request=request, product_id=product_id)
```

---

## 5. 一括実行（最短手順）

セットアップ済みなら、次の 2 コマンドで完了します。

```powershell
md-drf-codegen extract examples\specs\product-structure.md
md-drf-codegen generate examples\generated\product-structure.yaml
```

検証を挟む場合:

```powershell
md-drf-codegen extract examples\specs\product-structure.md
md-drf-codegen validate examples\generated\product-structure.yaml
md-drf-codegen generate examples\generated\product-structure.yaml
```

---

## 6. 生成結果の確認

構文チェック:

```powershell
python -m compileall -q examples\generated\product-structure
```

生成テストを含む pytest:

```powershell
pytest
```

ツール本体のみ（生成物を除く）:

```powershell
pytest tests
```

---

## 7. 仕様変更時の再生成

1. `examples/specs/product-structure.md` の `API一覧` / `型定義` を編集する
2. `extract` →（任意で `validate`）→ `generate` を再実行する
3. `examples/generated/product-structure/` 配下は上書きされる

業務ロジックは `<prefix>_handlers.py` の `handle` 実装を差し替えてください。再生成で上書きされるため、恒久的な実装はプロジェクト本体側へ移す想定です。

---

## トラブルシュート

| 症状 | 確認点 |
| --- | --- |
| `MissingSectionError` | Markdown に `## API一覧` と `## 型定義` があるか |
| `MissingColumnError` | API一覧 / 型定義の必須列名が仕様どおりか |
| `TypeReferenceError` | API の request/response 型が api 型定義に存在するか |
| `SchemaValidationError` | YAML の version / method / path / 型名形式 |
| 生成コードの import 失敗 | `pip install -e ".[dev]"` 済みか、Django / DRF が環境にあるか |
